CAUSE:
  ImageMagick default memory limit = 7.46GB RAM
  Default map limit = 14.9GB
  Default disk limit = UNLIMITED
  Converting large PDFs created 8GB swap file!
  Also: convert created ALL pages as PNG at once
  before OCR, using hundreds of MB temp storage.

FIX:
  1. Set ImageMagick policy.xml limits:
     memory=128MB, map=256MB, disk=512MB
     File: /data/data/com.termux/files/usr/etc/
           ImageMagick-7/policy.xml
  2. Convert ONE page at a time using [page_num] syntax:
     convert "file.pdf[0]" page_000.png
     Delete each PNG immediately after OCR.
  3. Peak temp storage now = ~2MB only (one page)

KEY CODE:
  for page_num in range(num_pages):
      subprocess.run(["convert",
          f"{pdf_path}[{page_num}]", tmp_img])
      # OCR immediately
      tesseract(tmp_img)
      # Delete immediately
      os.remove(tmp_img)

Status: RESOLVED (alternative used) ✅
Date: 2026-03-07

CAUSE:
  pip install pymupdf tries to compile from source
  Requires: swig, libclang, BISON, PCRE2, Rust
  Fails on Android/Termux ARM64
  Downloads 400MB+ before failing

SOLUTION:
  DO NOT use pymupdf on Termux/Android
  USE INSTEAD:
  - ImageMagick (pkg install) → convert PDF to PNG
  - tesseract (installed with mupdf pkg) → OCR PNG
  - ghostscript (gs command) → for simple PDFs
  Pipeline: PDF → convert → PNG → tesseract → TXT
