SECTION 3 — TECHNICAL DECISIONS AND REASONING
==============================================================

WHY WE CHOSE THESE TOOLS:

Flask for UI (not Kivy):
Reasoning: Flask = browser-based, easier to build and maintain.
Kivy = native Android feel but complex compilation on Termux.
Decision: Flask first, upgrade to Kivy later if needed.
The browser UI runs on localhost:5000 = no internet needed.
"localhost" means the phone itself, not the internet.

requests library instead of groq package:
Reasoning: groq package requires pydantic v2 which requires Rust.
Rust = 160MB download on limited ship data.
requests = already installed, zero MB needed.
Same result, fraction of the cost.
Lesson: Always check if you can use what's already installed.

Groq API instead of OpenAI:
Reasoning: 14,400 requests/day free tier.
No payment needed for personal use.
Uses Llama3 model = very capable for our needs.
OpenAI requires credit card = barrier for Filipino users.

Gemini API backup:
Reasoning: Google account = most Filipinos already have one.
No credit card needed for free tier.
Problem found: old API keys can have exhausted quotas.
Solution: Always create key in NEW project for fresh quota.

Offline brain = Mistral 7B:
Reasoning: Ship internet = unreliable/limited.
Need AI that works with zero internet.
Mistral 7B = best balance of quality vs size for 8GB RAM phone.
Problem found: mistral-smart.gguf was corrupted (incomplete download).
Evidence: .aria2 file present = download was interrupted.
Symptom: garbage/symbol output instead of real text.
Fix needed: redownload on good WiFi.

RAM limiting for local models:
Reasoning: Full Mistral = needs 5GB RAM.
Phone only has 3.8GB available after OS.
Without limits = phone hangs and crashes.
Solution flags:
  -t 2       = only 2 CPU threads (keeps phone responsive)
  --ctx-size 512 = small memory window (~1.5GB usage)
  -ngl 0     = no GPU layers (safer, prevents crashes)
  -st        = single turn (answer and exit, don't wait)

Whisper for voice (not Google STT only):
Reasoning: Google STT needs internet.
Ship = unreliable internet.
whisper.cpp = runs fully offline.
Models found: ggml-small.bin (466MB) and ggml-tiny.bin (75MB).
language="en-PH" = Filipino English locale = better accent handling.

Plugin architecture:
Reasoning: Single monolithic Jarvis = hard to maintain.
Plugin system = drop .py file in folder = new feature.
Delete .py file = feature removed.
No code changes needed in main jarvis.py.
Each plugin is independent = one crash doesn't break others.

Compressor high temp → check cooling water, ambient temp, load

SECTION 7 — REASONING PATTERNS TO LEARN
==============================================================

PATTERN 1 — Data-conscious decision making:
When on ship with 10GB/month limit:
→ Check if package already installed before downloading
→ Use requests instead of groq (saves 160MB)
→ Check file size before every pip install
→ Save offline versions of everything possible
→ Download big files only on port WiFi

PATTERN 2 — Debugging approach:
When something fails:
→ Read the exact error message carefully
→ Identify the ROOT cause not the symptom
→ Example: "av compile fails" → root cause is Python 3.12 incompatibility
→ Find alternative that avoids the root cause entirely
→ Don't fight the error, route around it

PATTERN 3 — Niche thinking:
When competing in a crowded market:
→ Find the intersection of your unique skills
→ Maritime + Python + AI = almost nobody else has this
→ Smaller niche = less competition = easier to win
→ "Python developer" = lost. "Maritime automation specialist" = wins.

PATTERN 4 — Build on existing instead of replacing:
When upgrading a system:
→ Scan what's already there first
→ Use what works, fix what doesn't
→ Don't rewrite everything from scratch
→ Owner had more built than they remembered
→ whisper.cpp, flask, plugins all already there

PATTERN 5 — Offline-first design:
For ship use:
→ Assume internet will fail
→ Build offline fallback for everything
→ Online = better quality bonus
→ Offline = minimum viable always works
→ Auto-switch between modes seamlessly
